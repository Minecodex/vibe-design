# PR 与 CI 合并规则

本仓库默认主分支为 `main`。日常开发从最新主分支创建功能分支，将功能分支推送到组织仓库，再通过 PR 合并。

```sh
git fetch origin
git switch -c feature/your-change origin/main
git push -u origin feature/your-change
```

主分支由仓库规则集保护：必须通过 PR，必须通过 `CI` 检查，合并前必须同步最新主分支，禁止强制推送和删除。规则没有管理员绕过名单；目前不额外要求他人批准，PR 上的审查讨论必须解决。

`CI` 是固定名称的汇总检查。它在所有 PR 上运行，任一必需任务失败、取消或意外跳过都会失败，避免工作流名称或矩阵版本变化导致保护规则失效。检查来源限定为 GitHub Actions。

## 自动检查范围

每个 PR 还必须在隔离 SQLite 与真实后端上通过登录、创建项目、浏览器重载和持久化检查，覆盖桌面亮/暗主题。测试使用当前统一组件和管理员开通的测试账户，不调用真实提供商。

每次 v* 发布执行 release.yml：先通过同一提交的基础 CI，再原生构建 CPU amd64、GPU 镜像 amd64 与 ARM64 三种既有部署镜像，按正式入口在真实 MySQL/Redis 上执行 Alembic heads 迁移并启动两个 worker，使用生产前端构建和 Chromium/Firefox/WebKit 检查登录及项目持久化。只接受实际启动和测试成功的候选镜像；失败、取消或跳过均阻止 Release CI。GPU 镜像的当前通用服务路径在 CI 中验收，不声称无 GPU 的 Runner 已验证 CUDA 计算或硬件吞吐。没有定时任务；手动运行或 ci:release 标签可检查完整候选，工作流不推送镜像或创建公开版本。

Python 3.12 后端 pytest 全套；Node 24 前端 ESLint、Vitest 和 TypeScript/生产构建。使用明确的本地测试数据库与公开测试密钥，不读取生产环境文件或真实提供商凭证。

前端测试环境固定 `Asia/Shanghai`，与包含 `+08:00` 的时间显示 fixture 一致，避免 Linux runner 默认 UTC 造成跨平台断言差异；产品仍按用户所在环境显示时间。

数据库与异步事件循环按测试隔离；生成测试使用持久化的合成用户凭证，工作流单元测试显式隔离凭证查询。现行产品不通过许可证激活限制功能，旧记录不能改写提供商密钥。默认模型、模型别名、能力校验与计费引用同一注册表，兼容别名的参考图上限与价格也必须有回归测试。

迁移初始化保留已有应用 logger，避免同进程执行迁移后丢失诊断与失败日志。画布项目加载、版本冲突与自动保存由独立同步模块管理，控制器的文件长度约束和同步回归测试继续执行。

前端 fixture 使用完整的 HTTP 响应、对话状态与事件类型；退役事件标签继续作为故意无效的输入检查兼容与终态保护。组件连接检查跟随实际消费模块，不依赖操作系统换行或已经删除的无用解构字段。流结束清理的提前返回限制在独立清理函数中，避免覆盖发送过程的结果。

界面组件与纯函数、Hook 分开导出，聊天侧栏通过状态 Hook 的实际返回类型校验视图参数。协议归一化独立于 HTTP/SSE 传输，保留既有 camelCase 兼容字段；开放 JSON 内容先以 `unknown` 接收，再在消费处校验类型。非法工作区文件路径不进入文件列表，也不能中断后续流事件。表单交互、画布选择、文件事件与对话重放继续执行原有回归测试。

画布媒体、项目与最外层视图共享具体的渲染参数合同，完整的模型提供商与复制/粘贴操作必须从页面传到对应视图。视图文件执行类型检查，性能场景和单元测试使用符合实际合同的 DOM、模型能力与渲染 fixture；不能用关闭类型检查替代这些验证。

工作流也支持主分支 push 和手动运行。手动运行使用 Actions 页面的 Run workflow，选择待检查的分支；功能分支首次引入新工作流时，先创建 PR 触发检查。

Playwright 的部分场景依赖完整后端、媒体处理和外部提供商；本 CI 不把这些部署或真实模型验收算作已通过，继续按项目原有环境规范运行。

CI 失败会阻止合并。修复失败后在同一个功能分支继续提交，重新运行检查；不要通过删除必需检查或设置管理员绕过来把失败当作通过。

消息载荷、工具结果与文件版本使用 `unknown` 和具体 DTO，嵌套对象、字符串、标识与数组在消费处校验。画布全局元数据独立于画布元素，模型注册表兼容逻辑由共享模块处理。表格预览调用当前 Univer 的只读权限 API；测试保留存储、投影、自动保存、版本冲突与交互回放检查。前端门禁不采用历史 lint 基线，也不禁用 `no-explicit-any` 或减少原有测试。
